# 题目难度划分（微课堂）

> 口径：**内容特征先验（冷启动）→ 作答数据校准 → 人工标注优先**，
> 这也是当前主流题库产品（学科网 / 猿题库 / 学习通一类）的通行做法：
> 没有作答数据时靠内容特征与来源打先验，有了作答数据再用正确率校准，老师改过的一律以老师为准。

## 1. 为什么要重做

原实现把采集来源里的「难度值」字段直接映射成 `easy / medium / hard`。真机数据说明它不可信：

| 现象           | 真机实测                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------- |
| 分布畸重       | 36.7 万题里 `medium` 占 **66%**，`easy` 29%、`hard` 4.8%                                            |
| 跨学段自相矛盾 | 小学 `hard` **16,347** 道，高中只有 **95** 道                                                       |
| 同一题库无梯度 | 3,884 个题库里所有题难度**完全相同**，6,238 个只有 2 档                                             |
| 老师改不了     | 题目接口的校验 schema **漏了 `difficulty` 字段**且开了 `removeAdditional`，界面提交的难度被静默丢掉 |

## 2. 先验模型（`apps/api/src/domain/difficulty.ts`）

对每道题打 0–100 分，全部来自**可解释特征**，界面上能看到「为什么判成难」：

| 特征族       | 具体项                                                                                   | 方向                   |
| ------------ | ---------------------------------------------------------------------------------------- | ---------------------- |
| 学段/年级    | 小学 30 / 初中 45 / 高中 62 基准，年级内微调（三年级 +0、六年级 +4…）                    | 起点                   |
| 题型         | 判断题 −7、单选 0、填空 +2、多选 +6、解答/简答 +10                                       | 越开放越难             |
| 算式与公式   | 运算符、等号/方程、分数式 `\frac`、根式 `\sqrt`、乘方、绝对值、多位数字、括号嵌套深度    | 步数越多越难           |
| 小问数       | `(1)(2)(3)`、`①②③` 这类多步题每个 +2（上限 +6）                                          | 步骤数                 |
| 阅读量/建模  | 题干长度 >40/80/160/260 字分别 +1/+3/+6/+8；带图 +4                                      | 应用题、材料题、看图题 |
| 空位数       | 多空填空 2 空 +3、≥3 空 +5                                                               | 作答步骤               |
| 高阶认知目标 | 证明 +8、分类讨论 +8、方案设计 +7、规律探究 +6、存在性 +6、综合 +6、最值 +5、实际应用 +3 | 布卢姆高阶             |
| 来源卷型     | 升学/模拟/压轴 +6、综合 +5、期末 +4、期中 +2、单元 +1；基础/随堂 −4                      | 试卷难度               |
| 题库类型     | 课时配套 −4、章节 0、整卷试卷 +4                                                         | 教学定位               |
| 知识点标注   | 「-求参」+4、「综合」+3、「压轴/竞赛」+6；「概念/认识/初步」−3                           | 知识层级               |
| 来源旧标注   | 旧值 `hard` +5、`easy` −4（只作弱特征，不直接采用）                                      | 保留既有信号           |

分数只是中间量，**落库时按分位数分档**（`cutPoints`），保证全库结构合理：

- 三档 `difficulty`（`easy / medium / hard`）：按 **p30 / p80** 切 → 基础约 30%、中档约 50%、较难约 20%；
- 五级 1–5★（展示用，国内题库通用口径）：按 **p20 / p40 / p60 / p80** 切；
- 阈值存在 `settings.difficulty_cuts`，全库共用一套 —— 不会出现「界面 4★、库里 easy」这种自相矛盾；
- 样本 < 20 题时退回默认阈值，避免小样本把分档带偏。

真实数据抽样 1,000 题的实测结构：基础 **29.7%** / 中档 **50.4%** / 较难 **20.1%**，两端样例合理
（最容易：三年级「小明跑 100 米要用 16（ ）」17 分；最难：数轴+绝对值综合、多参数多项式 97–100 分）。

## 3. 作答数据校准

`calibrateScore(prior, {correct, total}, {k=20})`：Beta 先验收缩

```
p = (correct + 1) / (total + 2)          # 经验正确率（拉普拉斯平滑）
先验正确率 = 1 − 先验分 / 100
w = total / (total + k)                  # 样本越多越听数据
最终分 = 100 × (1 − ((1−w)·先验正确率 + w·p))
```

- 数据来自随堂练习（`attempts`）与考试（`exam_attempts`）的 `answers` JSON：`[{qid, answer, correct}]`；
- **简答题不自动判分**（`correct = null`）不作为难度证据；
- 样本 < `minSamples`（默认 5）不动，样本足了自动向真实正确率收敛；
- 校准过的题标 `difficulty_source = 'calibrated'`，之后的「重算先验」不会覆盖它。

## 4. 人工标注优先

- 老师在题目编辑里选了三档 → `difficulty_source = 'manual'`；
- 「重算难度」默认**跳过** `manual` 与 `calibrated` 的题（预览里如实报「保留人工 N 道」）；
- 只有 `--force-all`（脚本）或显式传 `keepManual=0` 才会覆盖；
- 建题/改题接口现在**接受 `difficulty`**（此前被 schema 丢弃，是「有下拉框但难度没被划分」的直接原因）。

## 5. 接口

| 方法 | 路径                                                      | 权限        | 说明                                                             |
| ---- | --------------------------------------------------------- | ----------- | ---------------------------------------------------------------- |
| GET  | `/questions/difficulty?bankId=`                           | 登录        | 难度现状：三档/五级/来源分布、未评估数、当前阈值                 |
| GET  | `/questions/difficulty/preview?bankId=`                   | 教师/管理员 | 预览（**不写库**）：会评估多少道、跳过多少、预测分布、两端样例题 |
| POST | `/questions/difficulty/apply?bankId=&dryRun=1`            | 教师/管理员 | 批量写回；`keepManual=0` / `keepCalibrated=0` 才覆盖人工与校准   |
| POST | `/questions/difficulty/calibrate?dryRun=0&minSamples=&k=` | 教师/管理员 | 用真实作答校准（默认只预演）                                     |

题库体检 `GET /banks/health` 的返回里新增 `difficulty`（三档/五级/来源/未评估/直方图）。

## 6. 运维

```bash
# 全库重算先验（人工与已校准的题不动）
sudo docker exec microclass-api node /app/ops/scripts/recompute-difficulty.mjs --dry-run
sudo docker exec microclass-api node /app/ops/scripts/recompute-difficulty.mjs

# 只重算某个题库 / 连人工标注一起重算
sudo docker exec microclass-api node /app/ops/scripts/recompute-difficulty.mjs --bank 1234
sudo docker exec microclass-api node /app/ops/scripts/recompute-difficulty.mjs --force-all

# 作答数据校准（先看预演）
sudo docker exec microclass-api node /app/ops/scripts/recompute-difficulty.mjs --calibrate --dry-run
```

- 全库 36.6 万题是**读密集**操作（题干+选项+答案），NAS 慢盘上要几分钟到十几分钟；
  脚本已关掉 `wal_autocheckpoint`、开大页缓存/mmap、收尾做 `wal_checkpoint(TRUNCATE)`，
  建议**停服独占执行**（同 `docs/ops-runbook.md` 的批量维护章节）；
- 难度是**可重算**的派生数据：模型升级后重跑即可，不需要改题面。
