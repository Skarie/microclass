# 视频挂载完全指南（把视频变成课时）

本篇讲清楚三件事：**视频放哪里**、**三种部署方式各自怎么配**、**出问题怎么查**。

| 方式                            | 适合场景                         | 优点                           | 代价                             |
| ------------------------------- | -------------------------------- | ------------------------------ | -------------------------------- |
| **A. 媒体目录扫描导入**（推荐） | 已有整理好的视频文件夹、成批上线 | 批量、可重复扫描、章节自动划分 | 需要把文件放到服务能读到的位置   |
| **B. 网页直接上传**             | 少量视频、临时补录               | 全在界面里完成                 | 受上传大小限制、占用数据目录磁盘 |
| **C. 外链 / 嵌入**              | 视频已在 B 站 / 腾讯 / 自建 CDN  | 不占服务器磁盘                 | 依赖第三方（可能限速、失效）     |

---

## 0. 先理解三个词

```
媒体目录（媒体根）  →  课程文件夹（绑定某个媒体目录下的子路径）  →  课时（一个视频 = 一条课时）
```

- **媒体目录（媒体根）**：服务器上的一个文件夹路径，是**白名单**——只有登记过的目录，后台才能读取。
  - 配置存在**数据库**（`settings.media_roots`），界面里加过就永久保留（重启不丢）；
  - `MC_MEDIA_ROOTS` 环境变量只在**首次启动、且库里还没有媒体目录时**播种一次（见第 2 节的坑）。
- **课程文件夹**：某门课程「绑定」媒体目录下的一个子路径（例如 `七年级上册`）。绑定后，该子路径下的视频才能被扫进这门课。
- **课时**：视频在平台里的记录，两种来源：
  - `source = folder`：扫描生成，**跟随文件夹变化**（文件夹里删了文件 → 可被清理；章节名跟随文件夹）；
  - `source = manual`：手工创建或网页上传，**永不被扫描自动删除**（文件丢了只提示）。
- 另有内置媒体根 **`uploads`**：网页上传的视频存在 `MC_DATA_DIR` 下，**不可删除**。

### 路径怎么写（重要）

| 写法                                                  | 解析方式                                            | 建议                                                      |
| ----------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| 绝对路径（`/volume1/media/math7`、`D:/videos/math7`） | 原样使用                                            | **推荐**，最不容易出错                                    |
| 相对路径（`media/math7`）                             | 相对**服务启动时的工作目录**（`process.cwd()`）解析 | 本地开发可用；systemd 要配合 `WorkingDirectory`，容易踩坑 |

> Windows 本地开发：JSON 里的反斜杠要转义（`"D:\\\\videos\\\\math7"`），**更推荐用正斜杠** `"D:/videos/math7"`，Node 会正确处理。

## 1. 在磁盘上整理视频目录

约定：**一级目录 = 章节**（默认规则）。

```
/volume1/media/math7/                     ← 媒体目录（登记这一层）
└── 七年级上册/                            ← 课程文件夹（课程绑定到这一层）
    ├── 第一章 有理数/                      ← 章节（chapterMode=first 时取这一层）
    │   ├── 1.1 正数和负数.mp4
    │   ├── 1.2 有理数.mp4
    │   └── 1.3 有理数加减法.mp4
    ├── 第二章 整式的加减/
    │   ├── 2.1 整式.mp4
    │   └── 2.2 整式的加减.mp4
    └── 复习课-期末考试串讲.mp4              ← 直接放课程文件夹根目录 → 归入「未分章」
```

命名建议：

- 用**序号开头**，平台按**自然序**排序（`2. xxx` 排在 `10. xxx` 前，不会像字符串那样把 10 排到 2 前面）；
- 文件名去掉扩展名后就是课时标题；`第一章 有理数` 这类目录名会成为章节名；
- 支持常见容器/编码（`.mp4 / .mkv / .mov / .webm / .avi` 等）；浏览器不能直接播的封装，请先转成 H.264 + AAC 的 MP4；
- 网络盘（SMB/NFS）：先确认**已挂载**且服务用户可读，再登记；扫描大量文件时网络盘明显更慢，建议优先本地盘。

## 2. 配置媒体目录（三种部署方式）

> **共同的坑（先看这条，能省很多时间）**
>
> `MC_MEDIA_ROOTS` **只在「库里还没有任何媒体目录」时**写入数据库一次。
> 如果你已经用界面加过媒体目录，**再改环境变量不生效** —— 要么继续用界面加，要么先清空数据库里的
> `settings.media_roots`，或删掉数据目录重来（会丢数据，谨慎）。
> 查看当前生效值：界面「课程管理 → 媒体目录」，或 `GET /api/v1/media-roots`。

### 2.1 Docker（容器）

**要点**：宿主机目录要用 `-v` 挂进容器，`path` 填**容器内路径**（不是宿主机路径）。

```bash
docker run -d --name microclass \
  -p 8091:8091 \
  -e MC_ADMIN_PASS='强密码' \
  -e MC_MEDIA_ROOTS='[{"id":"math7","name":"数学·七年级","path":"/media/math7"}]' \
  -v microclass_data:/app/data \
  -v /volume1/media/math7:/media/math7:ro \
  microclass:2.0.0
```

compose 等价写法：

```yaml
services:
  microclass:
    image: microclass:2.0.0
    ports: ['8091:8091']
    environment:
      MC_MEDIA_ROOTS: '[{"id":"math7","name":"数学·七年级","path":"/media/math7"}]'
    volumes:
      - mcdata:/app/data
      - /volume1/media/math7:/media/math7:ro # 只读挂载，够用且更安全
```

- **新增目录**：改挂载 → 重建容器（数据卷保留）→ 界面「媒体目录」里加**容器内路径**；
- **诊断**：

```bash
docker exec microclass sh -c 'ls -l /media/math7 | head'
docker exec microclass sh -c 'head -c 16 "/media/math7/七年级上册/第一章 有理数/1.1 正数和负数.mp4" | wc -c'
```

### 2.2 本地 / 服务器直接运行（npm start、systemd）

**要点**：没有容器，`path` 直接填**宿主机绝对路径**；关键是**运行服务的系统用户**要能读到这些文件。

```bash
# 前台试跑：绝对路径最稳
MC_ENV=production \
MC_DATA_DIR=/srv/microclass/data \
MC_MEDIA_ROOTS='[{"id":"math7","name":"数学·七年级","path":"/srv/media/math7"}]' \
npm start
```

**systemd**（服务以 `microclass` 用户运行）：

```ini
[Service]
User=microclass
WorkingDirectory=/opt/microclass
EnvironmentFile=/opt/microclass/.env
ExecStart=/usr/bin/node apps/api/dist/server.js

# 媒体目录只读就够；数据目录要可写
ProtectSystem=strict
ReadWritePaths=/srv/microclass/data
ReadOnlyPaths=/srv/media                     # ← 只读放开媒体目录
PrivateTmp=true
```

- 用相对路径时必须让 `WorkingDirectory` 指向预期目录，否则会解析到别处（所以推荐绝对路径）；
- 开了 `ProtectSystem=strict` / `ProtectHome` 而**忘了 `ReadOnlyPaths`** → 读不到（表现为目录"不可用"或播放 403）；
- **SELinux**（RHEL/CentOS 系）：给目录打允许访问的标签，例如 `chcon -Rt httpd_sys_content_t /srv/media/math7`（按你的策略调整）；
- **AppArmor**（Ubuntu）：检查 `/etc/apparmor.d/` 是否限制了 node 的读路径。

验证（用服务用户身份试读）：

```bash
sudo -u microclass test -r "/srv/media/math7/七年级上册/第一章 有理数/1.1 正数和负数.mp4" && echo 可读 || echo 不可读
sudo -u microclass ls -ld /srv /srv/media /srv/media/math7      # 父目录需要可穿越
curl -s localhost:8091/api/v1/media-roots | head -c 300          # 看注册结果与可用状态
```

### 2.3 fnOS FPK（飞牛 NAS）

FPK 是 **native 应用**（不是容器），因此 `path` 直接填 **NAS 上的真实路径**，不需要 `-v` 映射。

1. 先在 NAS 上放好视频，例如 `/vol1/1000/media/math7/七年级上册/...`；
2. 配媒体目录，二选一：
   - **界面添加（推荐）**：课程管理 → 媒体目录 → 添加 → 填 `/vol1/1000/media/math7`（写入数据库，升级不丢）；
   - 或在 FPK 启动环境里注入 `MC_MEDIA_ROOTS='[{"id":"math7","name":"数学·七年级","path":"/vol1/1000/media/math7"}]'`。
3. 权限：应用进程以安装用户身份运行，需要它对该目录**有读权限**：

   ```bash
   ls -ld /vol1 /vol1/1000 /vol1/1000/media /vol1/1000/media/math7
   # 父目录要可穿越、目录与文件要可读；必要时（评估后）：
   # sudo chmod o+x /vol1/1000 && sudo chmod -R o+rX /vol1/1000/media/math7
   ```

4. 验证（注意 FPK 实例端口是 **8092**）：

   ```bash
   tail -20 /vol1/@appdata/microclass/info.log              # 启动日志
   curl -s localhost:8092/api/v1/media-roots | head -c 300   # 注册结果
   ```

5. 升级 FPK 时数据目录与媒体目录配置都保留；**只有 `/tmp` 下的临时文件会丢**。

### 2.4 不配环境变量，直接用界面添加（三种方式都适用）

**课程管理 → 媒体目录 → 添加媒体目录**，填 `名称` + `路径`：

- Docker：填**容器内路径**（`/media/math7`）；
- 本地/systemd：填**宿主机绝对路径**；
- fnOS FPK：填 **NAS 真实路径**。

添加后写入数据库、重启保留；此后 `MC_MEDIA_ROOTS` 的播种不再生效（设计如此，避免覆盖你在界面里的调整）。

## 3. 让课程认到这些视频

1. 管理员登录 → **课程管理** → **媒体目录** 标签页 → 应看到登记的目录及文件数（显示"不可用"就是路径/权限问题，见第 4 节）。
2. **课程** 标签页找到目标课程 → 点卡片进入 **管理课时**。
3. 点 **绑定视频文件夹** → 选媒体目录 → 选子路径（例如 `七年级上册`）。
4. **先预览扫描（dry run）**：只列出「会新增 / 会更新 / 会清理」，不动数据库。
5. 确认无误后**正式扫描**。

扫描选项：

| 选项            | 含义                                                                                           | 建议                                        |
| --------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `chapterMode`   | 章节名规则：`first`=取课程文件夹下**第一层**目录（默认）；`full`=完整相对路径；`none`=不设章节 | 素材是「章/节/视频」时用 `full`             |
| `removeMissing` | 磁盘上已消失的 `folder` 课时是否清理                                                           | 确认是「真删了」再开；`manual` 课时不受影响 |
| `onDuplicate`   | 同路径已在别门课时：`assign`=收编到本课程；`skip`=跳过                                         | 换绑课程用 `assign`，只想新增用 `skip`      |

**幂等保证**：已存在的课时不会重复创建；**新课时插到「同章节最后一条之后」**，手工拖拽调好的顺序不会被下次扫描打乱；重复扫描只做增量。

## 4. 权限（三种部署方式都要看）

统一症状：**目录显示"不可用"**，或**播放返回 403 `文件不可读：请确认应用运行用户对媒体目录有读权限`**。

| 部署方式     | 运行用户                               | 处理                                                                                |
| ------------ | -------------------------------------- | ----------------------------------------------------------------------------------- |
| Docker       | 容器内 uid 10001（或 `--user` 指定的） | ① `--user 1000:1000` 以媒体属主运行并把数据卷改属主；② 或放开媒体目录读权限         |
| 本地/systemd | `User=microclass` 指定的系统用户       | `chown`/`chmod` 让该用户可读；检查 `ProtectSystem`/`ProtectHome`、SELinux、AppArmor |
| fnOS FPK     | 应用安装用户                           | 确认父目录可穿越、目录与文件可读；必要时（评估后）放开读权限                        |

```bash
# Docker
docker exec microclass sh -c 'head -c 16 "/media/math7/xxx.mp4" | wc -c'
# 本地/systemd
sudo -u microclass head -c 16 "/srv/media/math7/xxx.mp4" | wc -c
# fnOS FPK：以应用用户试读，或直接看 info.log 与界面上的"可用"状态
```

**只读就够**：媒体目录不需要写权限，`-v ...:ro` / `chmod a-w` 都不影响播放与扫描。

## 方式 B：网页直接上传

1. **课程管理 → 课程 → 管理课时**，或 **全部课时 / 未归类课时** 标签页（三处都能传）。
2. 点 **上传视频**，选文件、填写**章节**（可新建或选已有），提交。
3. 完成后课时即出现在列表里，`source = manual`。

注意：

- 上限由 `MC_MAX_VIDEO_MB` 控制（默认 2048 MB），**改完要重启服务**生效；
- 文件落在 **`MC_DATA_DIR`**（内置媒体根 `uploads`）→ **备份数据目录就等于备份这些视频**；
- 需要时长/封面时确保有 `ffprobe`、`ffmpeg`（见第 6 节）；
- 上传走分片请求，中途失败可重试；**上传过程中不要重启服务**（会留下不完整文件，删掉该课时重传）。

---

## 方式 C：外链 / 嵌入（B 站、腾讯、自建 CDN）

1. 课时编辑里把**视频来源**切成外链/嵌入，粘贴播放地址或平台提供的 **iframe 嵌入代码**；
2. 保存后到观看页确认能出画面。

- **HTTPS 混合内容**：平台是 `https://` 时外链也必须 `https://`，否则被浏览器拦截；
- **防盗链**：部分平台校验 Referer，建议改用其官方嵌入方式，或把视频放到自己的对象存储/CDN；
- **进度记录**：平台仍按播放器事件记录进度，但第三方播放器行为差异大，"断点续播"不如本地文件稳定；
- 外链课时不占服务器磁盘，也**不参与**媒体目录扫描的清理逻辑。

## 5. 章节自动划分规则（`chapterMode`）

以课程文件夹为基准：

| 目录结构                             | `first`（默认） | `full`                         | `none` |
| ------------------------------------ | --------------- | ------------------------------ | ------ |
| `第一章 有理数/1.1 正数和负数.mp4`   | 第一章 有理数   | 第一章 有理数                  | 未分章 |
| `第一章 有理数/1.1 正数和负数/a.mp4` | 第一章 有理数   | 第一章 有理数 / 1.1 正数和负数 | 未分章 |
| `复习课.mp4`（根目录）               | 未分章          | 未分章                         | 未分章 |

章节名**跟随文件夹**：文件挪到别的章节目录，重扫后课时章节会同步更新；手工改过章节名的 `manual` 课时不会被覆盖。

## 6. 时长与封面

- 平台用 `ffprobe` / `ffmpeg` 读取时长并抽一帧做封面；
- 未安装也能用，只是**时长显示为空、封面为占位图**；
- 配置：`MC_FFPROBE_PATH` / `MC_FFMPEG_PATH`（默认从 PATH 探测）；
- Docker 镜像已内置 ffmpeg（`INSTALL_FFMPEG=0` 可裁剪，见 [deploy.md](deploy.md)）；
- 个别损坏/特殊编码的文件探测失败，只缺时长封面，不影响播放。

---

## 7. 播放机制（为什么体验是这样）

- 视频通过 **HTTP Range** 流式返回（`GET /api/v1/lessons/:id/video`），能**拖动进度条**、边下边播
  → 反向代理**不要**缓冲响应（Nginx `proxy_buffering off`，见 [deploy.md](deploy.md)）；
- 平台记录**最远观看位置**用于断点续播；把进度条直接拖到最后**不算看完**（防"拖到底刷完"）。

## 8. 排错

| 现象                             | 原因                                                               | 处理                                              |
| -------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------- |
| 媒体目录显示"不可用" / 文件数 0  | 路径写错（Docker 填了宿主机路径 / 相对路径解析到别处）；目录不存在 | 用第 2 节对应方式的诊断命令确认路径；改用绝对路径 |
| **改了 `MC_MEDIA_ROOTS` 不生效** | 库里已有媒体目录，环境变量只在首次播种                             | 用界面添加；或清空 `settings.media_roots`（谨慎） |
| 扫描不到文件                     | 路径不在白名单；扩展名不支持；只有临时文件（`.part/.tmp`）         | 核对路径；换成常见视频扩展名                      |
| 播放 403「文件不可读」           | 运行用户没有读权限（含 systemd 加固、SELinux）                     | 见第 4 节                                         |
| 播放 404                         | 磁盘上文件已删/改名，课时还在                                      | 重扫（可开 `removeMissing` 清理 `folder` 课时）   |
| 能播放但拖不动进度条             | 反向代理缓冲了响应                                                 | 反代加 `proxy_buffering off`，并透传 `Range`      |
| 上传失败                         | 超过 `MC_MAX_VIDEO_MB`；反代 body 限制；磁盘满                     | 三处一起调：env、`client_max_body_size`、磁盘     |
| 时长/封面为空                    | 没有 ffprobe/ffmpeg 或探测失败                                     | 配置路径 / 用带 ffmpeg 的镜像                     |
| 同一视频两条课时                 | 手工建过又被扫描到（或换绑课程用了 `assign`）                      | 「全部课时」搜索标题删掉多余的；下次扫描用 `skip` |
| 手工课时被扫描删了？             | 不会：`manual` 课时永不自动删除                                    | 检查是否手工删过，或换了数据库                    |

## 9. 最小可用流程（照着做一遍）

**Docker**

```text
1) 宿主机放视频：/volume1/media/math7/七年级上册/第一章 有理数/1.1 正数和负数.mp4
2) 启动容器（容器内路径 + 只读挂载）：
     -v /volume1/media/math7:/media/math7:ro
     MC_MEDIA_ROOTS=[{"id":"math7","name":"数学·七年级","path":"/media/math7"}]
3) 确认权限：docker exec microclass sh -c 'head -c 16 "/media/math7/...mp4" | wc -c' → 16
4) 后台 → 课程管理 → 媒体目录：看到 math7 且文件数 ≥1
5) 新建课程「初中数学·七年级上册」→ 管理课时 → 绑定视频文件夹：math7 / 七年级上册
6) 预览扫描 → 确认清单 → 正式扫描（chapterMode=first）
7) 课时列表出现「第一章 有理数」→「1.1 正数和负数」；学生端能播、能拖、能续播
```

**本地 / systemd**：同上，只把第 2 步换成「`MC_MEDIA_ROOTS` 填宿主机绝对路径（`/srv/media/math7`）」，
unit 里加 `ReadOnlyPaths=/srv/media`（若启用加固），第 3 步用 `sudo -u <服务用户> head -c 16 ...`。

**fnOS FPK**：同上，第 2 步填 NAS 真实路径（`/vol1/1000/media/math7`），第 3 步用
