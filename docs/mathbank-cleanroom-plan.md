## 三、独立实现计划（按性价比排序）

### P0 题组与变式关联（纯自主设计）

目标：把「同一考点的母题 + 若干变式」关联起来，组卷时可整组抽题，错题本可按组复习。

- 数据表（自行命名）：`question_groups(id, title, note, created_at)`、`question_group_items(group_id, question_id, role, sort)`，`role` 取 `stem`/`variant`。
- 接口：`POST/GET/PUT/DELETE /api/v1/question-groups`，`POST /api/v1/question-groups/:id/items`（批量关联/移除）。
- UI：题库题目详情侧栏「所属题组」；列表支持按题组筛选；组卷工作台提供「整组抽题」开关。
- 与现有能力关系：不改变题目表结构，只加关联表；不影响已有导入/组卷/考试。

### P1 自由标签 + 高级检索

- `tags(id, name, scope)`、`question_tags(question_id, tag_id)`；标签由管理员维护，题目可多标签。
- 检索：在现有题库筛选条上加「标签」多选 + 知识点「任意/全部」两种模式（对应 `ANY`/`ALL` 语义，本项目自行实现 SQL 逻辑）。
- 与知识点区别：知识点用于教学归属，标签用于教研标记（如「易错」「高考真题」「自编」）。

### P2 试卷导出增强（不做 LaTeX 编译）

- 现有打印页已能满足 A4；补充「导出为单文件 HTML（内联样式 + 图片 base64）」与浏览器打印 PDF 指引，避免在服务端引入 TeX 工具链。
- 如需 Word：复用现有 docx 导出能力扩展试卷结构（本项目已有 `docx` 依赖用于知识点导出）。

### P3 OCR / AI 辅助（可选、默认关闭）

- 定位为**外部服务插件**：OCR/大模型都通过服务端代理调用，密钥仅存服务端环境变量，前端不接触。
- 只用于「题目录入辅助」与「解析草稿」，结果必须人工确认后入库；不自动改答案。
- 优先接入国内可用的通用 OCR/多模态接口；接口层抽象成 `AiAssistProvider`，便于替换。
- 软著注意：提示词、返回结构、交互流程自行设计；不复制对方 prompt。

## 四、风险与边界

1. **法规**：AGPL 代码零复制；功能对标属于思想层面，允许。
2. **数据**：OCR/AI 会把题目内容发往第三方，需在系统设置里明确开关与隐私提示，默认关闭。
3. **成本**：OCR/大模型按量计费，需在设置页显示「由管理员配置的密钥」与用量提示。
4. **质量**：AI 解析只能作为草稿，必须经过人工确认，避免错误答案进入题库。

## 五、验收方式（每期）

- 单元测试覆盖新增数据层与接口（沿用现有 vitest 基线只增不减）。
- E2E 覆盖一条主流程（题组关联 → 组卷整组抽题 → 打印预览）。
- 设计守卫、行数守卫、Impeccable 检测器保持不变。
- 每期独立提交，提交信息写明「自主实现」，便于软著举证。
