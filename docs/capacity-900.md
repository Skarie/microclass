# 900 人同时看视频 + 答题：可行性与实施方案

> 目标：单套部署支撑 **900 人在线**，边看视频边答题，不出错、不卡顿。
> 本文件基于 2026-10 真机实测（NAS：Intel N150 / 16GB / 1GbE / 磁盘 1.3GB/s）。

## 一、先算带宽：这是唯一的硬墙

实测出口：**当前默认路由走 WiFi（`wlp4s0` 192.168.0.105）**，有线口 `enp2s0`（1000 Mb/s）接在
另一个网段（192.168.31.25）未被使用。之前实测 WiFi 下：单流 1.3 MB/s（10.5 Mbps）、8 路并发合计 26 Mbps。

抽样视频：1280×590、**4.5 Mbps**。

| 条件                        | 900 并发所需                             | 结论                |
| --------------------------- | ---------------------------------------- | ------------------- |
| 现状：WiFi + 4.5 Mbps       | 4 Gbps（且 WiFi 实际只有几十 Mbps 可用） | ❌ 差两个数量级     |
| 有线 1GbE + 4.5 Mbps        | 4 Gbps vs 可用 ~0.9 Gbps                 | ❌ 超 4 倍          |
| 有线 1GbE + 480p ≈ 1 Mbps   | 0.9 Gbps                                 | ⚠️ 打满，无抖动余量 |
| 有线 1GbE + 360p ≈ 0.5 Mbps | 0.45 Gbps                                | ✅ 可行，留一半余量 |

**结论：900 人看视频 = 必须「走有线」+「把默认码率降到 360p/480p」，二者缺一不可。**
若业务要求 900 人看 720p 以上，1GbE 物理上不可能，只能上对象存储/CDN 或 2.5G/10G 网络。

## 二、答题：实测 + 归一化

实测（1064 题的超大题量试卷，NAS 真机）：

| 并发 | 交卷 p50 | 看课 p50 / p95 | 失败 |
| ---- | -------- | -------------- | ---- |
| 60   | 7.0 s    | 26 / 45 ms     | 0    |
| 200  | 30.4 s   | 115 / 182 ms   | 0    |
| 500  | 41.9 s   | 241 / 585 ms   | 0    |

交卷耗时 ≈ 题量 × 并发（题均 0.08~0.14 ms）。折算真实 20 题卷：

| 并发 | 20 题卷 p50 |
| ---- | ----------- |
| 500  | ≈ 1.6 s     |
| 900  | ≈ 2.9 s     |

**没有任何失败**（无 5xx/429/写冲突），问题是"慢"而不是"错"。要达 900 人体验，必须：

1. **交卷异步判分**：同步只写 1 行 attempt + 答案 JSON → 响应毫秒级，与题量无关；
2. **批量写入**：逐题 upsert 合并成多行 `INSERT ... ON CONFLICT`；
3. 已做：限流按会话计数（3000/min）、视频 Range 与静态资源不计入限流、WAL 上限 + 定时 checkpoint。

## 三、实施顺序（每步都可单独验收）

### P0 网络（零成本，必须先做）

- 把 NAS 接入学生所在交换机：给 `enp2s0` 配 192.168.0.x（或调整 OVS 桥接），确保默认路由走有线；
- 验收：`ip route get 192.168.0.1` 出口为 `enp2s0`；客户端单流下载 ≥ 80 MB/s（1GbE 理论 110 MB/s）。

### P1 视频降码率 + 静态服务

- ffmpeg 批量转档：源 4.5 Mbps → 360p(500k) / 480p(1M) / 720p(2M) 三档，`-movflags +faststart`；
- 播放器默认 480p，网络差自动降档（HLS 或按码率选档）；
- 媒体改由 nginx（sendfile + cache）服务，Node 只管 API；
- 验收：900 并发拉 360p 档，网卡吞吐 < 700 Mbps，失败率 0。

### P2 答题异步判分

- `POST /exams/:id/submit` 改为：校验 → 写 attempt（含答案 JSON）→ 返回 attemptId → 后台判分并落成绩；
- 前端交卷后跳成绩页，轮询/推送判分完成；
- 验收：900 并发交卷 p95 < 1 s，失败率 0。

### P3 混合压测（最终验收）

- 900 并发：70% 看视频（360p）+ 20% 答题 + 10% 浏览课程；
- 观察：网卡吞吐、p95、错误率、SQLite busy、内存；
- 验收线：错误率 0、交卷 p95 < 1 s、看课 p95 < 1 s、网卡 < 700 Mbps。

### P4 不够才上外部

- 视频迁 对象存储/CDN（OSS+CDN、火山 VOD），NAS 只留 API 与数据；
- 或升级 2.5GbE/10GbE 网络（成本与改造量最大）。

## 四、当前实测能力（不等改造，今天能扛多少）

# API 并发（交卷 + 看课）
MC_ADMIN_PASS=xxx LT_BANK_ID=<有题的题库> LT_COURSE_ID=<该题库所属课程> node build/loadtest.mjs 200 both
