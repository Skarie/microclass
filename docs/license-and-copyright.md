## 2. 为什么不再用 MIT

MIT 允许商用、允许闭源改造，只要求保留版权声明 —— 与「**不允许商用**」的诉求直接冲突。
需要"广泛使用但要防止被白嫖商用"的另一条常见路线是 **AGPL-3.0**（允许商用，但提供网络服务必须开源）；
本项目的选择是**更严格**的非商业许可。

## 3. 想商用怎么办

1. 在仓库 **Issue** 里开一条标题为「商业授权申请」的议题（或按 README 中的联系方式）；
2. 说明：使用场景、规模（学校/机构/公司）、是否对外分发或收费、是否修改；
3. 双方签署**书面商业授权**后生效。

## 4. 软件著作权（软著）与「被人抢注」的风险

### 4.1 先厘清一个事实

- 著作权**自作品创作完成即自动产生**，无需登记；软著登记只是**初步证据**，**不等于**登记人就是真正作者。
- 他人拿你的代码去登记，**不能对抗你的在先著作权**，但会给你带来举证与维权的麻烦 —— 所以要提前布防。

### 4.2 最有效的防御：自己先登记

- 在中国版权保护中心做**软件著作权登记**：材料通常是源代码**前 30 页 + 后 30 页**（每页 50 行）+ 软件说明书 + 申请表；
- 周期约 1–3 个月，官费低；**登记时间越早，越能压制抢注**；
- 建议在首次公开发布（如首个 Release）之后尽快办理。

### 4.3 保留证据链（维权时决定胜负）

- **本仓库的 git 提交历史**：每次提交都有时间戳与内容哈希，且已推送到 GitHub（第三方时间戳）；
- GitHub 的 **Release / tag**、CI 运行记录、Issue/PR 讨论；
- 设计文档、原型截图、与需求方的沟通记录；
- 建议：给重要里程碑打 **tag + Release**（例如 `v2.0.0`），形成公开的时间锚点。

### 4.4 发现被抢注时怎么做

1. 其登记**不能对抗你的在先权利**；可向中国版权保护中心提出**异议/撤销请求**；
2. 可依《著作权法》主张**停止侵害、消除影响、赔偿损失**；
3. 证据优先级：**早于其登记日的公开时间戳**（git/GitHub 记录）+ 完整的创作过程材料 + 许可文本；
4. 若对方还违反本许可（商用、去除声明），同时构成**违约与侵权**。

## 6. 常见问题

**Q：学校/培训机构内部用来上课，算商用吗？**
非营利教育机构的教学使用属于许可允许范围；**以营利为目的的培训机构**属于商业用途，需要授权。

**Q：公司内部搭一套给员工学习用，算商用吗？**
属于"为商业利益的使用"（经营性内部使用），按本许可需要商业授权。

**Q：我只是学习/二次开发练手，能改吗？**
可以，只要不商用、保留声明、并把同样的许可传递给下游。

**Q：我能把它打包卖钱吗？**
不可以。

**Q：我自己写的插件/主题，必须也用这个许可吗？**
对你**独立创作、不含本项目代码**的部分，你可以自行决定；但一旦包含/链接本项目代码，就要遵守本许可。
