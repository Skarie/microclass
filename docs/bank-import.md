# 题库批量导入（教辅题库 → 微课堂）

本页说明如何把**已采集好的教辅题库**（按知识点组织的 Markdown + 图片）批量导入微课堂，
变成「课时 → 题库」的配套练习。

> **数据源（唯一）**：NAS 上的 `/vol2/1000/思酷睿课程/题库/` —— 含 `知识点索引.tsv`、
> `index.json`、`数学/ 物理/ 化学/` 三科目录，共 **465,428 个文件 / 8.0 GB**、
> **33.98 万道题 / 44.19 万张图**。容器里只读挂在 `/bank`；脚本按
> `MC_BANK_ROOT` → `/bank` → `/vol2/1000/思酷睿课程/题库` → 本机副本 的顺序自动选择数据源。
> 本项目早期用的本机副本 `题库_教师版` 与 NAS 内容**逐字节一致**（`知识点索引.tsv` sha256 相同、
> 文件数 465,428、`题目.md` 11,352 个、抽样文件哈希一致），现在统一以 NAS 为准。
>
> 整个过程**只读**原题库、**只写**微课堂自己的数据库与图片目录。

## 1. 数据长什么样

原始题库按「知识点」一个目录存放：

```text
题库/
  知识点索引.tsv     # 学科 / 书册 / 章节 / 知识点 / 题目数 / 单选 / 填空 / 图片数 / 路径
  index.json         # 同上，JSON 结构（学科 → 书册 → 章节 → 知识点）
  structure_*.json   # 按学科的结构快照；*_全部题目.jsonl 为全量题目导出
  数学/七年级上册/第一章 有理数（有理数的乘方运算）/有理数乘方/
    题目.md          # 人类可读：题目/选项/答案/解析/AI解析/难度值
    题目.json        # 同内容的结构化版本
    images/*.png
```

`题目.md` 里每道题的字段：`题目标识`（原平台题号）、`难度值`（≈正确率，越大越基础）、
`题目`、`选项`、`答案`、`解析`、`AI解析`（可选）、`解题方法`（可选）。

## 2. 四步流程

### 第 1 步：匹配「课时 ↔ 知识点」

```bash
node build/analyze-section-matching.mjs --write-report   # 按知识点名分层匹配，只读 + 写出 build/match-report.json
node build/diagnose-match.mjs                            # 没匹配上的课时长什么样（命名差异诊断）
node build/diagnose-unmatched.mjs "小学数学·一年级上册"    # 逐课时列出「视频小节/标题」与题库最相近的知识点
```

**关键点：用「小节目录名」而不是视频文件名去匹配**。视频目录是 `书册/章/[N.M 知识点/]视频.mp4`：

- 有第四层时，**小节目录名就是规范知识点名**（如 `1.10 圆锥的体积`、`3.6 表内乘法`）；
- 没有第四层时，文件名常写成「故事名-规范名」（如 `书海遨游-2、3、4的乘法口诀`、`魔力加法-9加几`），
  取破折号后半段即可。

匹配按 5 层递进（越靠后把握越低，`report.json` 里逐门课列出各层数量）：

| 层  | 含义                                                                | 说明                                   |
| --- | ------------------------------------------------------------------- | -------------------------------------- |
| T1  | 同书册 + 同章节 + 同知识点                                          | 最可靠                                 |
| T2  | 同书册（章节不同）                                                  | 视频与题库的章划分不同（版本不同）时用 |
| T3  | 同名册（题库里可能有「X年级上册（新）」「X年级上册（北师大版…）」） | 按归一化书册名找                       |
| T4  | 同学科（先同阶段：小学/初中/高中）                                  | 只认 ≥4 字的具体知识点名               |
| T5  | 模糊包含（「9加几」⊂「9加几的进位加法」）                           | 同书册 ≥3 字、跨阶段 ≥5 字             |
| T6  | 核心名匹配（去数字、去通用词后的包含/同义）                         | 合并式名字与说法不同，见下             |

**T6 补的两类命名差异**（二年级就是卡在这里）：

- **合并式名字**：`2、3、4的乘法口诀` 对应题库里 `2的乘法口诀及应用` / `3的…` / `4的…` 三条
  → 允许多条命中并**合并成一个题库**（该课时 133 题）；
- **说法不同**：`乘法的初步认识` ↔ `初步认识乘法意义`（去通用词后同为「乘法」）；
- **约束**：核心名必须互相包含；两边都有数字时**数字集合必须有交集**（`5的乘法口诀` 不会命中
  `2的乘法口诀`）；「点比课时更笼统」时要求点核 ≥4 字且长度接近课时核
  （否则 `用乘法口诀求商` 会命中泛化的 `乘法口诀`）。命中多条按内容去重合并，单题库上限 150 题
  （`MC_MAX_BANK_QUESTIONS` 可调）。

**实测：3,768 个课时里 3,674 个（97.5%）有配套题库**。剩下 65 个课时的清单在
`build/unmatched-lessons-v2.csv`（每个课时附 3 条**建议知识点**与相似度），照它填人工映射即可。

### 第 2 步：生成题库包（离线，Windows/Linux 均可）

```bash
# 一门课
node build/build-bank-manifest.mjs "初中数学·七年级上册"
# 或按匹配率批量打包（每门课一个包，可中断重跑）
node build/build-all-packs.mjs --min-rate 30        # 产物 build/packs/NN-<课程>.tar.gz + index.json
```

产物在 `build/import-pilot/`：

| 文件                | 说明                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| `manifest.json`     | 题库清单：题库名、`lessonId`、题目数组、匹配到的知识点与匹配层级     |
| `images/<sha1>.ext` | 题面引用到的图片，**内容寻址**（同一张图只存一份）                   |
| `report.json`       | 匹配明细（T1–T5 各层数量、实际用到的书册）、跳过原因、未匹配课时清单 |
| `unmatched.csv`     | 未匹配课时清单（课程/章节/小节目录/课时标题/视频路径），供人工映射   |

生成时的**文本归一化**（原始数据里确实存在这些问题，导致过题干显示异常）：

- `##` / `###` / `______` 都是「空位记号」→ 统一成 `____`（行首的 `## 标题` 不会被误改）；
- 采集时被 JSON 转义污染的内容：`\\frac{3}{4}` → `\frac{3}{4}`、字面量 `\n` → 真换行
  （`\neq`、`\nu` 这类 LaTeX 命令不受影响）；
- 填空题答案编码：**空与空之间**用 `；`，**同一个空的多种等价写法**用 `|`
  （原数据的 `@@` 表示等价写法、`$…$` 包裹会被去掉）。例如
  `-\\frac{3}{4}@@-0.75；4；5` → `-\frac{3}{4}|-0.75；4；5`；
- 难度：`难度值 ≥ 0.7 → easy`、`≥ 0.4 → medium`、其余 `hard`（微课堂题库管理页可按难度筛选）。

### 第 3 步：导入

题库包传到服务器后，用镜像内置的导入脚本执行（脚本会写入镜像的 `/app/ops/scripts`）：

```bash
# 传一门课的包并导入
scp build/packs/01-xxx.tar.gz <user>@<NAS-IP>:/tmp/
ssh <user>@<NAS-IP>
sudo docker exec microclass-api mkdir -p /tmp/pack
sudo docker cp /tmp/01-xxx.tar.gz microclass-api:/tmp/pack.tar.gz
sudo docker exec microclass-api tar -xzf /tmp/pack.tar.gz -C /tmp/pack

# 先干跑（只统计、不写题目；图片仍会按内容去重落盘）
sudo docker exec microclass-api node /app/ops/scripts/import-bank-manifest.mjs /tmp/pack --dry-run
# 正式导入（可加 --limit 20 灰度）
sudo docker exec microclass-api node /app/ops/scripts/import-bank-manifest.mjs /tmp/pack
# 用完清理容器内的包
sudo docker exec microclass-api rm -rf /tmp/pack /tmp/pack.tar.gz
```

多个包时用批量脚本（按包名记账，可中断重跑）：

```bash
# 推荐：题库包直接在宿主机解包，容器通过只读挂载 /import 读取（不必 docker cp 大包）
#   compose 里已挂： - /vol1/1000/microclass-bank-import:/import:ro
sudo bash /tmp/evo4-import-mounted.sh /vol1/1000/microclass-bank-import/packs
# 旧方式（把包拷进容器）：sudo bash /tmp/evo4-import-packs.sh <包目录>
```

### 第 3.5 步：全量导入（不止匹配到课时的部分）

「课时配套题库」只覆盖能匹配到知识点的课时；本地题库里还有两块内容，用 **sweep 模式**一并导入：

```bash
# 本地：把没进平台的部分打成包（章节题库 + 整卷试卷；默认并发 4，单包 ≤3.5 万题）
node build/build-sweep-packs.mjs                     # → build/sweep/NN-<分组>.tar.gz + index.json
# 传到 NAS 后按包名批量导入（与上面同一个脚本）
sudo bash /tmp/evo4-import-mounted.sh /vol1/1000/microclass-bank-import/sweep
```

- **章节题库**（`kind=chapter`）：没匹配到课时的知识点，题库名形如
  `五年级上册 · 1 小数除法 · 除数是整数的小数除法`，不挂课时，可浏览、可组卷；
- **整卷试卷**（`kind=paper`）：`综合题 / 期中 / 期末 / 单元测试` 各成一份整卷，
  管理端可 **一键建考试**（`POST /banks/:id/exam`）。

参数：

| 参数             | 作用                                                        |
| ---------------- | ----------------------------------------------------------- |
| `--dry-run`      | 只统计不落库                                                |
| `--limit N`      | 只处理前 N 个题库（灰度）                                   |
| `--lesson-id ID` | 只处理指定课时（可重复）                                    |
| `--course-id ID` | 只处理指定课程                                              |
| `--replace`      | 覆盖已有题库的题目（课时库按课时、章节/试卷库按题库名定位） |
| `--kind KIND`    | 只处理某一类题库：`lesson` / `chapter` / `paper`            |
| `--no-backfill`  | 已有题库不再回填标准化元数据（默认会回填）                  |

导入脚本的关键行为：

- **幂等**：课时配套题库以 `lesson_id` 为幂等键（一门课时一个题库）；章节题库 / 整卷试卷没有课时归属，
  以**题库名**为幂等键。重复执行不会产生重复题目，已有题目的题库默认跳过
  （输出里会显示「跳过（已有题）」的数量），但会**自动回填标准化元数据**；
- **标准化元数据**：每个题库写入 `kind/subject/book`，每道题写入
  `subject/stage/book/chapter/point/source_path/source_no/content_hash`（详见
  [bank-standardization.md](bank-standardization.md)）；老包的 manifest 缺 `subject/book` 时，
  从 `source` 路径与书册名推导，保证升级包格式不会让元数据留空；
- **图片**：调用与网页上传同一个 `QuestionMediaStore`，按**文件头**重新识别类型并落盘到
  `<数据目录>/uploads/question-media/<sha1 前两位>/<sha1>.<ext>`；若落盘文件名与包内文件名不同，
  自动改写题面里的引用（实测 7,848 张里有 10 张属于这种情况，已自动改写）；
- **一道题多张图**：图片直接内联在题干/选项/解析里（`![](/api/v1/question-media/<sha1>.png)`），
  前端按富文本渲染；同时把题干里的第一张图按**存储相对路径**写进 `image_path`
  （`question-media/xx/<sha1>.<ext>`），旧版 `/question-images/:id` 与 Word 导出都能取到这张图；
  前端在「题干里已有内联图片」时不会重复渲染它；
- **审计**：写入一条 `question_bank.import` 审计日志（题库数/题目数/图片数）；
- 结果同时写到包目录下的 `import-result.json`（干跑写 `import-dryrun.json`）。

> 性能实测（EVO4，机械盘数据卷）：5,616 道题首次导入约 30 秒；`--replace` 覆盖 159 个题库约 5 秒
> （删除旧题同样走一个事务，逐条提交在这块盘上会慢到十几分钟）。
> 批量导入多门课时用 `build/evo4-import-packs.sh`（按包名记账，可中断重跑）。

## 3. 已知取舍（如实记录）

| 事项                  | 现状                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------- |
| 未匹配课时            | 章节内没有对应知识点的课时**不会被强行塞题**（宁缺勿错），清单见 `report.json`                             |
| 原题号                | `题目标识` 不入库（微课堂没有该字段），仅在需要回溯时用 `report.json` 对照原目录                           |
| 大题（解答题/多小问） | 原数据里数量很少；按 `short` 类型导入，不自动判分，学生与参考答案自行比对                                  |
| 多选题                | 这批数据里没有多选题，导入器已支持但未经真实数据验证                                                       |
| 难度值语义            | 用「正确率」近似难度（≥0.7 基础），与原平台的星级评价不等价                                                |
| 图片格式              | 仅接受 png/jpeg/gif/webp/bmp（与网页上传白名单一致，不含 SVG）；不支持的文件会被计数跳过                   |
| 磁盘占用              | 图片内容寻址去重后仍不小（实测 5,616 题约 86 MB）；导入前先确认数据目录剩余空间                            |
| 判分口径              | 填空题**逐空比对**：空数不符或任一空不匹配即判错（数学等价写法要靠原数据里的 `@@` 备选，不会自动推等价式） |
| 公式渲染              | 题干/选项/解析里的 `$…$` 由 KaTeX 渲染；导出 Word 时公式仍是 LaTeX 源码（Word 里不排版公式）               |

### 实测覆盖情况（全量导入：课时配套 + 章节题库 + 整卷试卷）

| 指标         | 数值                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 有题库的课时 | **3,674 / 3,768（97.5%）**                                                      |
| 题库总量     | **12,276 个**：课时配套 3,675 / 章节题库 7,088 / 整卷试卷 1,513                 |
| 题目总量     | **366,865 道**（含同一知识点被多个课时共用的情况，原始题库 33.98 万题全部纳入） |
| 三类题量     | 课时配套 105,967｜章节题库 200,040｜整卷试卷 60,858                             |
| 题面引用图片 | 去重后 **8 万+ 张 / 1.5 GB**（按内容寻址，跨册共享同一张图）                    |
| 元数据覆盖   | 学科/书册/知识点/内容指纹 均 **366,790 / 366,865**（余下 75 道是用户自建题目）  |
| 题库体检     | 重复题分组 71,281（涉及 306,056 道）｜同题不同答案 771 组｜未标难度 21 道       |

**剩下 65 个课时没有题库**：清单在 `build/unmatched-lessons-v2.csv`（附每个课时的 3 条建议知识点与相似度），
集中在**小学数学一年级/二年级/三年级**（视频是北京版等版本，题库对应册的章节与知识点命名不同，
例如「时空穿梭机-认识时间」对应题库「时、分的认识及换算」），以及少数初中/高中零散课时。
这些课时**不会被强行塞题**（宁缺勿错），要补需要人工确认一张「课时 → 知识点」映射表。

## 4. 回滚

- **单个题库**：题库管理页删除该题库即可（题目随题库级联删除），图片是共享的，不删更安全；
- **整批回滚**：导入前先做一次备份（`npm run backup`），需要时按 `docs/ops-runbook.md` 第 3 节恢复；
- 导入**不会**修改课程、课时、视频与原有手工题库。
